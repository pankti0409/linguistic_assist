Open-source does not mean everything runs offline.

The app uses open-source libraries, an open-weight language model hosted by Groq, and hosted recognition/voice/avatar APIs. An open-source SDK is the connector, not ownership of the service or its model.

Where each kind of data goes.

Stays on the laptop

Device control, MediaPipe face/gesture tracking, fragment cleanup, validation, confirmation, and optional vocabulary files.

Uses cloud services

Audio goes to Scribe; text evidence goes to Groq; eligible lip video goes to the HF Space; approved voice/avatar output uses ElevenLabs and Tavus/Daily.

Optional local lip model

Auto-AVSR + PyTorch can replace the hosted Space when source and a compatible checkpoint are installed. Code and weight licences are separate.

The details that matter.

Partner: same recognition, different purpose

A partner question is recorded through the same local microphone and Scribe service. It is saved as speaker-labelled conversation context. The patient’s next words can use that context. Example: “Water or tea?” + “water … cold” → “I would like cold water, please.” Speaker roles are selected explicitly; there is no automatic diarization.

Confirmation, auto-say, and the output ladder

Our validator checks the model response before review. A single-use confirmation ID binds the exact text. Optional auto-say offers a 3-second cancel/edit window for eligible candidates; lip-only evidence is excluded. Edited wording is shown back. Output tries Tavus audio echo, then text echo, then local voice audio/subtitles. An earlier successful tier stops later tiers from speaking too.

Current deployment, not a claim of perfect availability

Current configuration: real mode, gpt-oss-20b through Groq; scribe_v2 and eleven_flash_v2_5 through ElevenLabs; HF lip Space marshal-yash/vsr_trlrs3vox2_base; MacBook Air Microphone. Backend: 8765. Frontend: 5173. Services still depend on permissions, credentials, provider availability, and optional avatar sessions.

Lip recognition: the actual data handling

The currently configured hosted path writes a temporary MP4, uploads it to the HF Space, and deletes it in a finally block. It is therefore not entirely memory-only and not entirely local. Audio is also sent to ElevenLabs for recognition. Only text and derived evidence are sent to Groq. Some older README privacy wording predates this path.

Landing demo and video tools are separate

The landing studio uses labelled examples and optional browser SpeechSynthesis. The cinematic hero uses WebGL/Canvas/video. Offline rembg/U²-Net, Pillow, SciPy, OpenCV, and FFmpeg preparation builds those visual assets; it does not perform patient recognition.
